# Миграции

`V1__init.sql` — начальная схема, эталон, не редактируется.

Свои миграции добавляйте следующими номерами: `V2__...sql`, `V3__...sql` и т.д.
(стандартная схема именования Flyway: `V<версия>__<описание>.sql`).

## Порядок применения в ЛР3

1. `V2` добавляет `customers`, внешние ключи и обратную совместимость для
   старых записей в `orders` и `order_items`. Старые колонки остаются доступными.
2. `V3` добавляет `first_name`/`last_name`, переносит имена и синхронизирует
   старое и новое представления имени. После `V3` можно развернуть новую версию
   приложения: она читает новые поля, а триггеры поддерживают старые поля.
3. Когда старых экземпляров приложения больше нет, `V4`, `V5`, `V6` удаляют
   старые поля по одной таблице за миграцию. Последней удаляется
   `orders.customer_full_name`, которую читает старый код.

При поэтапном развёртывании применяйте миграции Flyway до нужной версии
отдельно от запуска приложения. Иначе Spring Boot по умолчанию применит всю
цепочку сразу при старте.

В этой ветке `V2` переработана для поэтапной миграции. Если существующая
локальная БД уже применяла `V2` из ветки ЛР2, Flyway обнаружит другую
контрольную сумму. Для учебного прогона используйте новую БД. Если в старой
БД есть нужные данные, сохраните их и согласуйте обновление истории Flyway
с фактической схемой перед запуском новой версии.
